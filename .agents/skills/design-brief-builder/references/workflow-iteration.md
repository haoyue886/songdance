# 设计规范迭代

先区分实现调整与方向变化。明确的局部 UI 修正直接实现；改变布局原则、视觉系统、交互结构或已有 Brief 约定时，更新相应设计依据。

1. 读取受影响的 Brief 条目、设计稿和实际界面，提取用户已确定的新方向。
2. 判断冲突。最新明确要求可取代旧决定；涉及核心操作、信息层级或多处复用时检查连带影响。只有无法推断的关键取舍才问。
3. 局部修改设计规范，保持未受影响的原则、编号和结构。参考只在有助于解决当前未知时补查，不为每个风格词重启采访。
4. 在用户已授权范围内同步相关设计稿和实现，并进行适用的视觉验证；只要求文档时说明未执行的下游变化。

完成标准是受影响界面可据此实现且各文档不互相矛盾，不是再次确认全部设计方向。
