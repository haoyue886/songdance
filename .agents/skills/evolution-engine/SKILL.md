# 规则改进

先读 `.codex/EVOLUTION.md` 和本次相关证据。只读所需 signals、proposals 和提交 diff；不在每次启动时全扫历史，也不把重复 fix 提交自动判定为规则缺陷。

在“补充上下文、增加测试/工具、改现有规则、新建技能”之间选最小有效改动。保留领域事实，避免为了泛化而删除复现条件。项目专属信息放项目文档，通用规则才进技能。

每项建议包含失败证据、原因假设、目标文件、改动、验证场景和潜在副作用。没有足够证据可以不给建议。没有对照实验时不能声称模型能力或速度已经提升。

子 Agent 只读分析并向主 Agent 返回建议，不消费队列、不写规则。主 Agent 根据本次授权处理；已授权的 harness 优化不逐条重复审批。未授权的新偏好或范围变化留作待审。

处理记录保留来源和处理结果，合并重复项；不以清空队列代表问题解决。优先删除无效或重复约束，新增规则需要能解释具体收益。
