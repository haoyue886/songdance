# 长期目标

根据现有上下文生成简洁、可验证的目标。只有会改变交付结果的信息缺失时才问；不让用户重新描述已知项目。

明确用户要的是“准备指令”还是“现在开始目标”。准备指令只输出可复制文本；明确要求创建或启动目标时，按当前可用能力执行。不要把某个历史版本的字符限制、evaluator 机制或 slash 命令假设成通用规则；依赖具体能力前核实。

可用结构，删掉不适用项：

```text
完成 <具体目标>。
完成标准：<可观察终态及证据>。
验证：<相关检查/实际操作>。
边界：<范围、明确禁止事项、对外操作授权>。
```

有事实阻塞时如实记录已完成工作和剩余条件，不要求穷尽无关尝试。普通任务已经可以持续执行，不把创建额外目标当作完成开发的前提。
