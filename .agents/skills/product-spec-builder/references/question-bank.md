# 产品需求问题库

按缺失维度查阅，问题是可改写的提示，不是必答题。信息可来自用户、现有文档、代码或合理默认；无需固定数量、固定顺序和逐项确认。

## 1. 用户、问题与结果

**要弄清**：主要使用者、任务发生的情境、当前做法及期望结果。

**可问**：
- “用户在什么情况下打开它，最后要完成什么？”
- 探索真实需求时：“最近一次遇到这问题，具体怎么处理、花了什么代价？”
- “哪些可观察变化说明这个版本有用？”

**足够的结果**：可以描述主用户和目标任务，有可判断成败的信号。全新实验可以把价值判断记为假设，不要求虚构经历或收入数字。

## 2. 范围与优先级

**要弄清**：本次必须交付什么，哪些留到以后，哪些明确不做。

**可问**：“如果只保留最短可用路径，哪些能力仍必需？哪些可以暂缓？”

**足够的结果**：首版或本次范围可验收，依赖闭合。非目标和 P0/P1 用于表达真实取舍，不设条数下限，也不强迫把合理的多个核心功能砍成一个。

## 3. 用户任务、流程与功能

**要弄清**：目标任务、端到端路径、每步触发和结果。

**可问**：
- “从打开产品到完成任务，用户依次做什么、看到什么？”
- “这一步由什么触发，拿什么输入，输出什么，失败后还能做什么？”
- “创建或导入的资源，之后如何修改、删除、归档或退出？”

**足够的结果**：核心路径没有断点，主要分支明确，用户目标与实现手段可分辨。若使用 TASK / FLOW / REQ 编号，保持引用一致。

## 4. 数据与业务规则

**要弄清**：核心实体、关系、生命周期、权限、输入约束。

**可问**：
- “哪些数据要保存？谁能看或改？删除后还有哪些引用或保留要求？”
- “哪些输入必填，空值、重复、超长和错误格式如何处理？”
- “哪些操作必须同时成功，失败或重复提交时怎么办？”

**足够的结果**：业务层面的数据规则可实施，关键输入有校验和反馈。纯展示、无持久化的任务跳过无关模型细节；字段命名和内部 schema 可交开发决定。

## 5. AI 能力（仅相关功能）

**要弄清**：为什么需要 AI、输入来源、质量判断、触发方式、失败与成本。

**可问**：
- “需要生成、理解、检索现有资料，还是代用户执行多步操作？规则或普通搜索能否满足目标？”
- “哪些结果算可用，哪些错最不可接受？能否给有代表性的好坏样本？”
- “输出是草稿、建议还是直接执行？不确定、服务失败或过慢时如何处理？”
- “预期调用量、可接受延迟和成本约束是什么？”

**足够的结果**：有适合功能风险的评估办法、触发边界和降级路径。阈值未知时写成待验证目标与测量方式，不强行要求固定样本数、准确率或技术方案。

## 6. UI 与状态（仅有相应交互）

**要弄清**：主要区域、重要控件和适用状态。

**可问**：
- “最重要的操作和结果放在哪？是否有现成页面、设计稿或组件先例？”
- “首次使用或无结果时如何继续？等待、失败、权限受限和成功时分别给什么反馈？”
- “工作台的画布、预览、编辑区或结果表，哪些空间必须优先保留？”

**足够的结果**：主流程布局和关键状态不靠猜，状态只覆盖实际存在的情形。用户让你决定视觉细节时继承现有样式，不强制逐态询问或自增页面。

## 7. 验收、约束与未知

**要弄清**：可观察的完成条件、真实非功能约束、阻塞问题。

**可问**：
- “在这个前置状态下执行操作，最终应看到什么？”
- “实际支持哪些设备、数据规模、权限角色和恢复场景？”
- “哪项假设错了会造成大返工或不可接受结果？”

**足够的结果**：关键功能有可测试的主路径与异常验收，适用的性能、安全、隐私、兼容、可靠性和可访问性要求明确。不要凭模板增加无关仪表盘、合规流程或设备范围。

## 8. Agent 系统（产品会自主行动时）

| 维度 | 可问的关键问题 | 形成的决定 |
|---|---|---|
| 自主边界 | 哪些动作已授权自动做，哪些需要确认，哪些禁止？ | 与产品风险及用户授权一致的动作边界 |
| 工具与扩展 | 需要哪些工具？若兼容已有标准，需支持哪些包结构、资源和执行入口？ | 能力清单、权限边界和真实兼容范围 |
| 上下文与记忆 | 长任务超出上下文时如何继续？跨会话保留什么？ | 上下文策略与数据保留范围 |
| 编排 | 单 Agent 是否足够？并行工作的收益和合并方式是什么？ | 按任务选择编排，不默认强制多 Agent |
| 评估与可观测 | 如何发现任务失败、回归和质量退化？ | 代表性评估、动作记录和诊断办法 |
| 成本 | 什么资源可能失控，如何限制或停止？ | 与使用场景匹配的预算与停止条件 |
| 恢复 | 循环、卡住、工具失败后怎样处理已产生的结果？ | 重试边界、恢复办法与需要人介入的条件 |
| 会话 | 是否需要中断、继续和历史？ | 与任务时长相符的状态持久化范围 |

这些是产品规格维度，不改变当前执行环境的模型、工具权限或网络配置。短任务或明确不需要的能力可以省略。
