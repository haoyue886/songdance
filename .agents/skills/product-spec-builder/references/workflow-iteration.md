# 需求迭代工作流

适用于改变现有功能范围、业务行为、数据契约或验收标准的请求。

## 判断需要更新什么

- **实现细节**：文案润色、颜色、间距、明确控件位置或局部样式，不改变产品契约时直接实现。只有源文档确实记录了被改变的决定，才同步该处。
- **功能调整**：状态行为、输入输出、流程或数据规则改变，定位并更新对应需求与验收。
- **范围或结构变化**：新增主要功能、核心路径、外部能力或信息架构变化，补必要影响分析，并检查关联设计、计划与已有实现。

## 执行

1. 读现有相关条目和必要上下文，提取请求中已经确定的变化。
2. 查冲突和依赖。用户最新指令已明确改动方向时据此更新；只有多种解释会显著改变结果时才澄清。
3. 局部修改 Spec，保持编号和无关内容。按项目现有方式记录实质需求变更，可用 [变更记录模板](../templates/changelog-template.md)。
4. 检查相关 Brief、设计稿、DEV-PLAN 和实现是否受影响。已授权完整变更时继续同步；只要求文档时列明后续影响，不扩展成代码任务。
5. 核对变更后的主路径、异常与验收。没有新增关键疑问就继续，不设置固定确认关口。

采访深度随未知程度决定。明确调整可直接写入；复杂但资料齐全的变更也不必重新采访。需要追问时按 [问题库](question-bank.md) 找对应维度。
