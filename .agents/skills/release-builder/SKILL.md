# 构建与发布

从用户请求和现有部署文档确定产物、目标环境与授权范围。只打包时先完成本地产物；目标已明确时不重复问。缺失会影响发布的渠道、账号或环境时，先完成不依赖它的构建和检查。

## 验证实际产物

- 使用项目锁定工具链和实际配置构建。检查产物中的敏感数据、私钥、凭据和意外打包的数据文件；模式命中先核实，不把文档中的变量名当泄漏。
- 校验版本、依赖和目标平台兼容性；按当前渠道规则处理签名、上架、弃用和回退，不硬编码会变化的发布政策。
- 按项目包管理器和锁定依赖检查已知漏洞，核实严重级别及实际可达性；未处置的可达高危/严重漏洞阻塞发布。工具或网络不可用时标明未验证，不能写成无漏洞；误报须有依据。
- 在隔离目录或测试环境验证安装及关键流程。无需为了测试默认全局安装 CLI 或覆盖用户正式应用。
- 有异常查日志、依赖布局、进程及网络状态，CPU 空闲本身不证明死锁。
- 用实际受测提交/产物标识记录结果。用户的无关未提交改动不要求清掉，也不能混入发布。

## 对外操作

部署、发布及远端 Git 写入必须落在已有明确授权和目标内；已授权不重复审批，未授权先交付可审查产物再询问。完成发布后检查真实环境的健康和核心流程，失败时按约定回退或说明需要的操作。

最终报告产物位置、目标版本、验证证据、部署结果及剩余限制。构建成功不能等同线上可用，准备好配置不能等同已经部署。
