# 按需改进规则

当前任务优先。会话启动不自动扫描历史、不阻塞工作等待逐条批准；用户请求优化 harness 或出现值得归纳的重复失败时，再调用 evolution-engine。

## 证据与授权

- 普通的“删除按钮”“改成某样式”是产品需求，不靠关键词把整条用户消息记成纠正。
- 需要沉淀时记录最小必要摘要：问题、上下文、复现证据、可能影响的规则，避免存入密钥或整段私密对话。
- 新记录推荐包含 id、时间、summary、evidence、status。保留可读的旧记录，不为换格式丢失来源。
- `.codex/evolution/signals.jsonl` 是待分析材料，`proposals.md` 是候选建议和处理结果。存在建议不等于用户已同意。
- evolution-runner 只读分析并返回证据，主 Agent 负责记录和落实。先记录处理结果再标记来源已处理；不删除被否决记录来掩盖历史。

## 何时改

有明确 harness 优化授权时，主 Agent 可在该范围内实施并验证，无需每条重复确认。新的长期偏好、对外操作或范围扩大仍需相应授权。没有授权时保留建议，不抢占当前任务追问。

优先修工具、补针对性测试或缩小旧规则，避免一次失败生成一条全局禁令。每次改进都写可观察的预期与回归场景；没有真实任务对照数据就只报告结构改善，不宣称已提高完成率或速度。
